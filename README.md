# README.md и журнал работы с ИИ: гайдлайн

## Зачем это нужно

Каждый проект сдаётся с файлом `README.md` в корне репозитория, а в нём — подробный раздел о том, как команда работала с ИИ. Пользоваться ИИ можно; нельзя скрывать, где и как вы им пользовались.

README — это лицо проекта: по нему проверяющий, будущий работодатель или вы сами через год понимаете, что это за сайт, как его запустить и кто что сделал. Раздел об ИИ показывает, где решения ваши, а где сгенерированные, и насколько вы понимаете код, который сдаёте.

При проверке смотрим на четыре вещи:

- **Полнота.** Заполнены все обязательные разделы, ссылки работают.
- **Честность.** Описано всё значимое использование ИИ, включая неудачные попытки.
- **Понимание.** Вы можете объяснить любой фрагмент кода, даже если его предложил ИИ.
- **Рефлексия.** Вы оцениваете, где ИИ помог, а где ошибся, и что вы исправили.

## Где лежит README и как его писать

Файл называется ровно `README.md` и лежит в корне репозитория — тогда GitHub показывает его на главной странице проекта. Пишите его с первой недели и обновляйте вместе с кодом, а не за ночь до сдачи.

Минимум Markdown, которого хватит:

| Что нужно | Как написать |
| --- | --- |
| Заголовки разделов | `## Название раздела` |
| Список | `- пункт` или `1. пункт` |
| Ссылка | `[текст](https://адрес)` |
| Картинка | `![описание](docs/screenshot.png)` |
| Код в строке | текст в обратных апострофах: `npm run dev` |
| Блок кода | три обратных апострофа до и после блока |
| Таблица | ячейки разделяются вертикальной чертой, под заголовком — строка из дефисов (см. шаблон ниже) |

Скриншоты и вспомогательные файлы складывайте в папку `src/ai`, чтобы не засорять корень. Если журнал работы с ИИ получается длинным, вынесите его в `docs/ai-log.md`, а в README оставьте краткую сводку и ссылку.

Перед коммитом откройте предпросмотр: в VS Code — `Ctrl+Shift+V` (`Cmd+Shift+V` на Mac), на GitHub — вкладка Preview при редактировании файла.

## Обязательная структура README

README состоит из девяти разделов в этом порядке. Разделы 1–8 описывают проект, раздел 9 — работу с ИИ (подробно о нём ниже).

1. **Название и одна фраза о проекте.** Что это за сайт и для кого: «Медиа об уходе за домашними растениями для цветочных любителей».
2. **Ссылки.** Опубликованный сайт на GitHub Pages и макет в Figma. Проверьте, что макет открыт по ссылке на просмотр.
3. **Скриншоты.** Главная страница на десктопе и на мобильном, 2–4 изображения из папки `src/ai`.
4. **Команда и роли.** Кто что делал: верстка каких страниц, разработка макетов, адаптив, сборка, деплой, тексты. Конкретно, а не «все делали всё» или «я делал дизайн, а он код»
5. **Структура проекта.** Дерево основных папок с одной строкой пояснения к каждой начиная с папки `src`. То, что мы на предпросмотре смотрели Пример в `structure.md`.
6. **Решения и сложности.** 3–5 пунктов: что было непросто в верстке (сетка, адаптив, анимации, типографика) и как вы это решили. Что сознательно не сделали и почему.
7. **Использование ИИ.** Сводная таблица инструментов, журнал запросов, рефлексия.

## Раздел об ИИ: что фиксировать

Раздел об ИИ состоит из трёх частей: сводной таблицы инструментов, журнала значимых запросов и рефлексии. Фиксируйте всё: чат-ассистентов (GigaChat, YandexGPT, Claude, ChatGPT), ИИ в редакторе (Cursor, GitHub Copilot), агентов (Claude Code), генераторы изображений и ИИ-функции Figma.

### Часть 1. Сводная таблица инструментов

Одна строка на инструмент. Модель и версию берите из интерфейса инструмента.

| Инструмент и модель | Кто из команды | Для каких задач | Уровень участия |
| --- | --- | --- | --- |
| Cursor, Claude Sonnet | Маша | Адаптив главной, отладка сетки | 3 |
| GigaChat | Лёша | Объяснение `grid-template-areas` | 1 |
| GitHub Copilot | Все | Автодополнение в HTML и CSS | 2 |

### Шкала уровня участия ИИ

| Уровень | Что это значит | Пример |
| --- | --- | --- |
| 0 | ИИ не использовался | Верстка футера с нуля по макету |
| 1 | Объяснение и консультация, код ваш | «Чем отличается `auto-fit` от `auto-fill`?» |
| 2 | Подсказки и автодополнение мелких фрагментов | Copilot дописал медиазапрос |
| 3 | ИИ сгенерировал заметный фрагмент, вы его доработали | Компонент карточки, переписанный под дизайн-токены |
| 4 | ИИ сгенерировал фрагмент, вы приняли его почти без изменений | Конфиг GitHub Actions для деплоя |

### Какие задачи обязательно описывать

- Генерация разметки, стилей или скриптов длиннее 10 строк.
- Поиск и исправление ошибок: верстка «поехала», сборка не проходит, деплой упал.
- Рефакторинг и перенос кода: например, вынос повторяющихся блоков в шаблоны Eleventy.
- Настройка инструментов: конфиги Vite и Eleventy, GitHub Actions, тесты Playwright.
- Проверка доступности и семантики, ревью кода.
- Тексты на сайте, alt-тексты, изображения и иконки, созданные ИИ.

Автодополнение в редакторе на уровне одной-двух строк не нужно записывать в журнал по отдельности. Достаточно строки в сводной таблице.

### Метки в коде и коммитах

Фрагмент уровня 3–4 помечайте комментарием прямо в коде:

```css
/* AI: Cursor (Claude Sonnet), доработано: заменены отступы на токены, добавлен брейкпоинт 768px. См. ai-log #4 */
```

В сообщении коммита с таким кодом добавляйте метку `[ai]`: `[ai] адаптивная сетка карточек на главной`. Так проверяющий видит, какие изменения сделаны с ИИ, прямо в истории репозитория.

## Журнал запросов и рефлексия

### Часть 2. Журнал значимых запросов

Одна запись — одна задача, решённая с ИИ, даже если на неё ушло десять сообщений в чате. Записывайте сразу после работы, пока помните детали. Новые записи добавляйте в конец, нумеруйте по порядку.

В каждой записи семь полей:

1. **Номер, дата, автор.**
2. **Инструмент и модель.**
3. **Задача.** Что вы хотели получить, своими словами.
4. **Запрос.** Ключевой промпт дословно. Если запросов было много — первый и самый удачный, остальные кратко.
5. **Что выдал ИИ.** Кратко; длинный код не копируйте, дайте ссылку на файл или коммит.
6. **Что вы изменили и почему.** Самое важное поле: ошибки ИИ, расхождения с макетом, правки под дизайн-систему.
7. **Итог и проверка.** Где теперь этот код, как вы проверили результат: браузеры, ширины экрана, валидатор, тесты.

Пример записи:

```markdown
### #4 · 14.11.2026 · Маша

- **Инструмент:** Cursor, Claude Sonnet
- **Задача:** сделать сетку карточек на главной: 3 колонки на десктопе, 1 на мобильном, как в макете.
- **Запрос:** «Сверстай сетку карточек на CSS Grid без фреймворков. На ширине от 1024px — 3 колонки, до 768px — 1. Отступы бери из переменных в tokens.css.»
- **Что выдал ИИ:** сетку на grid-template-columns с repeat(auto-fit, minmax(280px, 1fr)) и два медиазапроса.
- **Что изменила:** ИИ проигнорировал переменные и поставил отступы 24px — заменила на var(--space-m). Убрала лишний медиазапрос: auto-fit и так даёт нужное поведение. Добавила промежуточное состояние в 2 колонки, которого нет в коде ИИ, но есть в макете.
- **Итог:** src/styles/cards.css, коммит a3f9c21. Проверила в Chrome и Safari на 375, 768 и 1440px.
```

### Часть 3. Рефлексия команды

В конце раздела — 5–10 предложений от команды. Ответьте на вопросы:

- Какие задачи ИИ решал хорошо, а в каких ошибался чаще всего?
- Какие ошибки ИИ вы нашли и как их заметили?

- Что сделали бы иначе в следующем проекте?

## Правила честной работы с ИИ

Главное правило: вы отвечаете за каждую строку в репозитории, кто бы её ни написал. На просмотре вас могут попросить объяснить любой фрагмент или изменить его на месте без ИИ.

| Можно | Нельзя |
| --- | --- |
| Просить объяснить свойство, ошибку, чужой код | Сдавать код, который не можете объяснить |
| Генерировать фрагменты и дорабатывать их под макет | Скрывать использование ИИ или занижать уровень участия |
| Использовать ИИ для поиска багов и ревью | Выдавать сгенерированные тексты и изображения за свои |
| Пробовать несколько вариантов и выбирать лучший | Переписывать журнал задним числом, «подчищая» неудачи |
| Записывать неудачные попытки | Показывать "идеальную версию" |

Рекомендации для команды:

- Каждый ведёт свои записи в журнале сам; автор записи — тот, кто работал с ИИ.
- Перед мерджем чужой ветки с меткой `[ai]` второй участник читает код и задаёт вопросы автору.
- Раз в неделю, на консультации с куратором, сверяйте журнал с историей коммитов.
- Если сомневаетесь, нужно ли что-то записывать, — записывайте. Лишняя запись не снижает оценку, пропущенная может вызвать вопросы.

На занятиях в аудитории доступны российские ИИ-сервисы, а дома — любые. Описывайте одинаково подробно и те, и другие.
